# 豆包 Passport 手机号登录端点可行性侦察

- 侦察时间：2026-10-17
- 关联需求：`REQ-DOUBAO-PROVIDER-20261017`（`doc/2-需求/2026-10-17_011146_豆包Provider插件立项需求.md`）
- 侦察目标：验证「手机号 + 短信验证码登录」路线可行性，回答认证方式变更后的 `GAP-001`（会话是否自带 `flow_cur_user_sec_id`）
- 结论：**端点真实存在，但完整登录链路未跑通；契约关键参数未解，需真实账号实测才能定论**

## 1. 侦察方法

对豆包 Passport 端点做**只读探测**，全部使用**无效号段 `00000000000`**，不向任何真实手机号发送短信。

探测判据：以**错误码语义**区分「端点不存在」与「端点存在但参数不对」——SPA 兜底页对所有路径都返回 200，故 HTTP 状态码无鉴别力，必须看响应体 `error_code`。

## 2. 探测结果

### 2.1 端点存在性矩阵

| 端点 | 响应 error_code | 描述 | 判定 |
|---|---|---|---|
| `/passport/web/send_code/` | `1003` | 手机号错误，请重新填写 | **端点真实**（能识别 mobile 字段并校验格式） |
| `/passport/web/sms_login/` | `1002` | 手机号为空，请填写手机号 | **端点真实**（业务级校验，非应用级拒绝） |
| `/passport/web/get_qrcode/` | `3` / `22` | 缺少参数 / 非法应用 | 真实（rex-zsd、doubao2api 均用此端点） |
| `/passport/web/login/` | `16` | 该应用无权限 | 存在但当前 aid 无权限 |
| `/passport/web/login_v2/` | `16` | 该应用无权限 | 同上 |
| `/passport/web/check_sms_code/` | `16` | 该应用无权限 | 同上 |
| `/passport/web/email_login/` | `16` | 该应用无权限 | 同上 |
| `/passport/web/mobile_login/` | `16` | 该应用无权限 | 同上 |
| `/passport/web/web_login/` | `1900` | 平台异常 | 存在但需完整上下文 |
| `/passport/web/nonexistent_xyz_123/` | `22` | 非法应用 | 对照组（不存在路径） |

**关键鉴别**：`send_code` 与 `sms_login` 返回的是**业务级错误码**（1002/1003，针对 mobile 字段本身），而其他候选端点返回 `16 该应用无权限`（应用级拒绝）。这说明**前者是豆包真实启用的短信登录端点**，后者不是该产品线的登录入口。

### 2.2 `send_code` 参数契约

已确认 `mobile` 字段被识别（返回 1003「手机号错误」而非「缺少参数」）。以下 payload 变体**均返回同一 1003**，说明 `mobile` 是正确字段名，其余为可选：

```text
{"mobile":"00000000000"}
{"mobile":"00000000000","type":1}
{"mobile":"00000000000","aid":"497858"}
{"mobile":"00000000000","type":1,"aid":"497858","mix_mode":"1"}
{"mobile":"00000000000","type":1,"mobile_ticket":""}
```

请求头：`Content-Type: application/json` + `User-Agent: Mozilla/5.0 … Chrome/131`。
必需 query：`aid=497858`（缺则返回 `22 非法应用`）。

### 2.3 `sms_login` 参数契约（未解）

以下 payload 变体**全部返回 1002「手机号为空」**，说明当前字段名均未被识别：

```text
{"mobile":"00000000000"}
{"mobile":"00000000000","code":"000000"}
{"mobile":"00000000000","code":"000000","type":1}
{"mobile":"00000000000","code":"000000","aid":"497858"}
{"mobile_ticket":"00000000000","code":"000000"}
{"phone":"00000000000","code":"000000"}
```

**推断**：`sms_login` 的入参不是原始手机号，而应是 `send_code` 阶段下发的**票据**（响应体含 `mobile_ticket` 字段，当前为空）。即两步机制：

```text
1. POST /passport/web/send_code/  {mobile}      → 下发 mobile_ticket（短信发往该号）
2. POST /passport/web/sms_login/  {ticket,code} → 换取会话 Cookie
```

`mobile_ticket` 字段名与消费方式**尚未验证**（需真实手机号走完 send_code 才能拿到非空 ticket）。

## 3. 未解问题（阻断项）

- `BLK-A`：`sms_login` 的真实入参字段名与 `mobile_ticket` 的传递方式未解。**必须用真实手机号完成一次 send_code** 才能拿到 ticket 并复现。
- `BLK-B`：验证码风控未知。豆包页面加载了字节跳动风控 SDK（`webmssdk.es5.js`），`send_code` 在真实号段上是否触发滑块/人机验证未知。
- `BLK-C`：**登录成功后的会话是否自带 `flow_cur_user_sec_id`** 未验证——这是原 `GAP-001` 的核心，手机号路线同样绕不开。
- `BLK-D`：`aid=497858` 是否对手机号登录有权限。`login`/`check_sms_code` 返回 `16 该应用无权限`，提示手机号登录可能需要另一个 aid（页面配置里另有 `1044603` 等候选）。

## 4. 横向参考：同类项目均未走手机号路线

| 项目 | 星数 | 认证方式 |
|---|---|---|
| `wangchuxiaoji-oss/doubao2api` | 281 | QR 扫码（`/passport/web/get_qrcode/` + `check_qrconnect/`，`AID=497858`，需 `passport_csrf_token` 头）+ Playwright 持久化浏览器 |
| `Bitsea1/doubao-free-api` | 222 | 未获取到 README 内容（抓取为空） |
| `Lxapk/DouBao-CPA-Plugin` | 0 | 粘贴浏览器 Cookie 快照 |
| `rex-zsd/doubao-cpa-plugin` | 0 | Passport 扫码 |

**结论**：四个已知豆包逆向实现中，**无一个采用手机号+短信验证码登录**，全部走扫码或 Cookie 快照。这本身是一个负面信号——手机号路线的风控（人机验证）可能显著高于扫码。

## 5. 下一步（需用户配合）

要关闭 `BLK-A`~`BLK-D`，必须执行一次真实手机号登录（会真实发送短信）：

1. 用真实豆包账号调 `send_code`（`aid=497858`），观察是否触发人机验证、拿到非空 `mobile_ticket`；
2. 用 ticket + 收到的验证码调 `sms_login`，确认字段名；
3. 检查返回的 Cookie 是否含 `flow_cur_user_sec_id` 与 `sessionid`；
4. 用该会话直连 `/im/send/message`，确认 IM 端点可用。
