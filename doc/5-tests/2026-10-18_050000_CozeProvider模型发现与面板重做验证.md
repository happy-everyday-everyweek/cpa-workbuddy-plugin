# Coze Provider 0.2.0 模型发现、面板重做与生产部署验证

- 时间：2026-10-18 05:00
- 版本：coze-provider 0.1.3 → 0.2.0
- 环境：本地（cgo-shim）+ 生产（cpa.luode.vip，容器 `cli-proxy-api`）

## 1. 需求来源

用户在生产管理台看到两个问题：

1. 管理台 `auth-files` 的「支持的模型」弹窗显示「该凭证暂无可用模型 / 该认证凭证可能尚未被服务器加载或没有绑定任何模型」；官网明明有语言模型与多模态（视频）模型。
2. 插件面板与 workbuddy 面板差距很大；不需要面板内授权区；缺测试模型功能；时间应显示北京时间。

## 2. 上游契约实测

用真实账号（`coze-00b200b641c48c1e`）实测两条模型来源：

| 端点 | 方法 | 契约 | 返回 |
|---|---|---|---|
| `/v1/model/list` | POST | `model_type` 必须是**字符串**枚举（`llm` / `image_generation` / `video_generation` / `tts` / `asr` / `embedding`），传数字返回 `InvalidRequest` | 逐类型目录 |
| `/api/coze_claw/resource/get_multimodal_model_catalog` | POST | body `{}`，返回 `capabilities[]`（`image_gen` / `generate_video`） | 生视频完整族 |

关键发现：`/v1/model/list` 的 `video_generation` 只有 1 条，Seedance 2.5 / 2.0 Pro/Fast/Mini、MiniMax-H3 只出现在多模态目录里，**两者必须合并**。

## 3. 实现

### 3.1 模型发现（`coze/models.go`）

- 6 个类型端点 + 多模态目录**并发**拉取，单请求超时 8 秒。
- 单类型失败不阻断整体；全部失败才返回错误（不伪造空目录为成功）。
- `is_offline` 模型不登记；按 `model_type` 映射宿主 `Type`（`chat` / `image` / `video` / `embedding` / `audio`）。
- 目录 ID 统一加 `coze/` 前缀，避免与其它 provider 同名冲突。
- 缓存 TTL 10 分钟，**按 `AuthID` 分桶**。
- `model.static`（宿主启动期同步调用）**只返回内置种子，不打网络**；真实目录由 `model.for_auth` 按账号提供。

### 3.2 面板探活（`coze/active_ping.go`）

| 路由 | 作用 |
|---|---|
| `GET /models?auth_id=` | 测试弹窗的模型下拉数据源；上游失败时回落内置清单并在 `notice` 说明原因 |
| `POST /test-active` | 认证层探活：判据端点 + 模型目录 + `sec_user_id` 归属 + 选中模型是否在目录 |

`scope: "auth+models"` 明确标注这是认证层探活，不是真实推理——真实对话链路需要 `claw_id` / `session_id`（CYCLE-01）。

### 3.3 面板重做（`coze/panel.html`）

- **移除**「授权扣子账号」引导区（3 步流程 + 脚本框）；授权统一走宿主「添加账号」弹窗。
- 按 workbuddy 风格：账号卡（状态徽章 / 身份字段 / 操作按钮组）、筛选标签 + 计数、账号汇总卡、搜索、全部启用/禁用、删除二次确认、右上角滑入通知、三态主题。
- 时间统一 `Asia/Shanghai` → `YYYY-MM-DD HH:mm:ss`。
