# Coze 定时续期自启动与落盘防覆盖验证

- 日期：2026-10-18
- 版本：coze-provider 0.2.2
- 范围：插件内定时续期循环、续期落盘链路、防覆盖判据修复
- 环境：Windows 10 + Git Bash（shim 单测）、WSL2 Ubuntu（真实 cgo + ctypes 探针）

## 1. 背景与结论

用户要求「定时 4 小时补 `refresh_interval_seconds`，续期和其他插件一样」。
0.2.1 只补了 metadata 字段，经宿主源码核实**不足以触发续期**：

```go
// sdk/cliproxy/auth/auto_refresh_loop.go:249-252
if exec == nil {
    l.upsert(authID, now.Add(l.interval))
    return
}
```

`RegisterExecutors` 只注册声明了 executor 能力的插件；coze 声明
`Executor: false`（对话链路未实现），因此宿主的 4 小时排期对本插件
只做空转重排，永远不会调用 `auth.refresh`。

**结论**：定时续期必须由插件自建（`coze/renew_loop.go`），0.2.2 已实现。

## 5. 真实 `.so` 探针（`test/coze/renew_loop_probe.py`）

用 ctypes 复刻宿主函数指针表，`cliproxy_plugin_init` 后**不做任何 HTTP
调用**，纯等后台循环自启：

```
PASS  cliproxy_plugin_init 返回 0
PASS  plugin.register 成功
PASS  init 后自启续期循环（出现轮次结束日志）
PASS  续期调用了 host.auth.list
PASS  续期向宿主日志上报账号数
PASS  续期尝试可观测（完成日志或失败日志）
PASS  Shutdown 后循环停止（无新 host 调用）

[coze] 7/7 PASS
```

**探针判别力验证**：注释掉 `startRenewLoop()` 后重建 `.so`，探针变为
3/7 PASS，4 项精确 FAIL（无轮次日志、`host.auth.list` 调用数 0）。

### 未覆盖项（诚实标注）

插件续期用独立 `http.Client` **直连 `www.coze.cn`**，不经宿主
`host.http.do`，探针在不做 TLS 中间人的前提下无法拦截上游往返。
因此「上游双向换发 + 落盘」由 Go 单测覆盖：

- `TestRenewSession_DoubleExchange`（Cookie→token→Cookie 两次往返）
- `TestRenewSession_SingleStepWhenCookiesReturned`
- `TestRenewSession_Rejected`
- `TestApplyRenewal_WritesNewCookie`
- `TestApplyRenewal_SkipsWhenExternallyReplaced`

## 6. 顺带修复的真实缺陷

`applyRenewal` 原有的防覆盖判据是**失效的**：

```go
if bindStore(sa.PhysicalPath).replaced() { ... }  // 写前才取摘要
```

`bindStore` 在调用瞬间才计算文件摘要，比对对象永远是文件自身，
外部重新授权写入的新凭据会被旧快照静默覆盖。该缺陷由
`TestApplyRenewal_SkipsWhenExternallyReplaced` 首次运行即暴露
（实际 `sessionid=renewed`，期望 `sessionid=external`），
已改为「读取时记录摘要（`StoredAuth.LoadedDigest`）、写入前比对」。

## 7. 判定

- 功能：4 小时定时续期已由插件内定时器实现，热重载后立即跑首轮
- 可观测：每轮通过宿主 `host.log` 上报账号数与成功数，失败带原因
- 安全：防覆盖判据修复，外部新凭据不再被旧快照覆盖
- 待生产验证：部署后等待 `last_renew_at` 在无手动点击下推进
