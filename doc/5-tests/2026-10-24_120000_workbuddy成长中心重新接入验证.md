## 2. 关键发现（与旧版对比）

### 2.1 旧版失败的真正根因

旧版完全没有调用 `buddy/first`。实测未领养 Buddy 时：

```json
{"code":0,"msg":"OK","data":{"results":[
  {"task_code":"chat_5","status":"error",
   "message":"prerequisite not met: first_buddy (no buddy instance found)"}
]}}
```

**全部任务**都被这条前置门槛挡住。旧版每轮都发 accept、每轮都被逐条拒绝，而它只看 HTTP 状态码，于是记成「14 accepted」，下一轮 pending 集合完全不变——这正是生产日志 `14 accepted, 0 claimed` 连续 6 轮恒定的完整解释。

领养后同一批任务立刻可用：

| task_code | 领养前 | 领养后 |
| --- | --- | --- |
| `first_buddy` | `not_accepted`，progress=null | `claimed`，progress={1,1} |
| `chat_5` | `not_accepted`，progress=null | `accepted`，progress={0,5} |

### 2.2 域名不是问题

四个 base 的 `/tasks` 全部返回 200：

```
https://www.codebuddy.cn/v2/activity/growth          200
https://www.workbuddy.cn/activity/growth             200
https://copilot.tencent.com/v2/activity/growth       200
https://copilot.tencent.com/activity/growth          200
```

此前怀疑「旧版路径错误」不成立；失败原因在业务前置门槛，不在路由。

### 2.3 上报确实点亮进度

连续 4 次 `POST /v2/report` 的真实观测：

```
before chat_5: ('in_progress', 1, 5)
  report#1 [200] chat_5: ('in_progress', 2, 5)
  report#2 [200] chat_5: ('in_progress', 3, 5)
  report#3 [200] chat_5: ('in_progress', 4, 5)
  report#4 [200] chat_5: ('completed', 5, 5)
claim chat_5: {"already_claimed":false,"credit":100,"energy":5}
after claim: ('claimed', 5, 5)
```

结算延迟约 3 秒（本实现用 `growthSettleDelay = 3s`）。

## 4. 真实端到端

方式：WSL 用 `CGO_ENABLED=1 -buildmode=c-shared` 编译真实 `.so`，
再用 ctypes 驱动 `cliproxy_plugin_init` / `management.handle`，宿主回调把
`host.http.do` 真实转发到上游。

实际请求序列（日志摘录）：

```

[host.http.do] GET  200 .../v2/activity/growth/buddy/quota
[host.http.do] POST 200 .../v2/report
[host.http.do] POST 200 .../v2/activity/growth/buddy/agreement
[host.http.do] POST 200 .../v2/activity/growth/buddy/first
[host.http.do] GET  200 .../v2/activity/growth/buddy/travel/status
[host.http.do] GET  200 .../v2/activity/growth/buddy/travel/config
[host.http.do] POST 200 .../v2/activity/growth/buddy/travel/depart
[host.http.do] GET  200 .../v2/activity/growth/tasks
[host.http.do] POST 200 .../v2/activity/growth/tasks/accept
[host.http.do] GET  200 .../v2/activity/growth/tasks
```

返回结果：


要点：
- 顺序正确（领养在任务段之前）
- `errors: null`，七段无失败
- 拆分文件后复跑结果一致

## 6. 未覆盖项

| 项 | 原因 |
| --- | --- |
| 补登 / 兑换 / 抽奖 / 盲盒写端点 | 有真实副作用（消耗补登卡、额度、次数、能量），探针纪律禁止探测性调用；由编排在满足条件时执行 |
| 浏览器点击验证 | 无运行中的 CPA 实例 |
| Global 账号路径 | 仅单测桩验证 `skipped_global`，无真实 Global 账号 |
| 25 项专属任务动作 | 明确不在范围（用户选定「通用上报层，专属动作只读」） |
