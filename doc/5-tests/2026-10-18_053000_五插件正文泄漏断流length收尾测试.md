## 2. 新增用例

### 2.1 TestBuildStreamTerminalChunk（五插件各 1 组）

校验合成终止分片的形态契约：

| 断言项 | 期望 | 理由 |
|---|---|---|
| `object` | `chat.completion.chunk` | 转译层 `root.Get("object")` 非此值会直接丢弃帧 |
| `model` | 传入的客户端模型名 | 下游按模型名路由与计费 |
| `choices` 长度 | 1 | 单候选流 |
| `finish_reason` | `length` | 触发 `incompleteByFinishReason` → `response.incomplete` |
| `delta` | 空对象 | 不得混入正文，否则污染已生成内容 |
| `streamChunkHasContent` | `false` | 终止分片不得被误判为内容泄漏（否则影响后续换号判定） |

### 2.2 TestBuildStreamTerminalChunkFraming（五插件各 1 组）

校验 SSE 前缀差异：

- 原始分片不带 `data: ` 前缀（原生 chat-completions 透传由宿主补）。
- 加前缀后 `data: ` 之后是合法 JSON（跨格式转译路径）。

## 3. 变异反证

对 qoderwork 执行两次变异，验证测试判别力：

| 变异 | 预期失败用例 | 实测结果 |
|---|---|---|
| `finish_reason` 改为 `stop` | `TestBuildStreamTerminalChunk` | **精确命中**：`finish_reason = "stop", want length` |
| `delta` 改为 `{"content":"x"}` | `TestBuildStreamTerminalChunk` | **精确命中**：`delta should be empty, got map[content:x]` |

两次变异均在还原后恢复全绿。

## 5. 未覆盖项（诚实标注）

| 项 | 原因 |
|---|---|
| 端到端「真实上游断流 → 插件合成 length → new-api 出 token」 | 需真实断流事件，无法在本地注入 |
| 宿主转译层 `response.incomplete` 的实际下发 | 已逐行核验代码（见 Bug 文档 §10.2），未做运行时验证 |
| 客户端（Codex / Qoder）对 `incomplete` 的续写行为 | 需真实客户端接入 |
| 同步路径（`StreamID == ""`） | 生产不可达，本轮明确不改 |
