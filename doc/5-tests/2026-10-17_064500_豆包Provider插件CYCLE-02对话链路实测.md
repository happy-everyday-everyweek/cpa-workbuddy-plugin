## 3. 关键发现：GAP-010 契约修正

初版按 Lxapk 参考实现构造请求体，真实上游返回 `710020202 common invalid param`。排查过程：

1. 用浏览器插件在页面上下文 hook `fetch`，捕获网页端真实 `/chat/completion` 请求体（2496 字节）；
2. 在页面内做 6 组字段消融（去掉 `conversation_init_option` / `conversation_mode` / `extra_info` 等），全部仍成功 → 说明差异不在这些可选字段；
3. 在页面内替换 URL query 为插件生成的参数集，仍成功 → 说明差异不在 query；
4. 回到纯 HTTP，把浏览器字段逐项补进插件请求体，**定位到唯一必需项**：`client_meta.local_conversation_id`。

补充验证（纯 HTTP）：

| 变体 | 结果 |
| --- | --- |
| `local_conversation_id` 缺失 | `710020202` |
| `local_conversation_id` 为空串 | `710020202` |
| `local_conversation_id` 为 `local_<16 位数字>` | 成功（`SSE_ACK` + 增量帧） |
| `local_conversation_id` 为 `local_<uuid>` | 成功 |

结论：该字段**必填且任意非空即可**，插件生成 `local_<UUID>` 填入。

## 4. SSE 事件语义（实测）

一次真实回复的事件序列：

```text
SSE_HEARTBEAT → SSE_ACK → FULL_MSG_NOTIFY(user_type=1) → STREAM_MSG_NOTIFY
→ STREAM_CHUNK ×2 → CHUNK_DELTA → STREAM_CHUNK → CHUNK_DELTA → STREAM_CHUNK ×3
→ SSE_REPLY_END(end_type=1) → SSE_REPLY_END(end_type=2) → STREAM_CHUNK ×3 → SSE_REPLY_END(end_type=3)
```

- 正文来自 `STREAM_MSG_NOTIFY` 首块 + `STREAM_CHUNK.patch_op[].patch_value.content_block` + `CHUNK_DELTA.text`，必须按到达顺序累加；
- `FULL_MSG_NOTIFY` 携带的是用户提问回显（`message.user_type=1`），**不得计入回复**；
- 正文在首个 `SSE_REPLY_END`（`end_type=1`）之前已全部到齐，其后的 `end_type=2/3` 只是推荐追问等附属信息，可立即停止读取（避免死等 Keep-Alive）。

6. **脱敏**：本文档不含 Cookie、`sec_user_id` 原值、会话 id 原值或手机号；日志仅输出长度。
