# 宿主 OAuth 登录页对三插件可用性实测（workbuddy-ai / traework / zcode）

- 被测对象：CPA 宿主统一 OAuth 登录入口 `GET /v0/management/<plugin-id>-auth-url` + `GET /v0/management/get-auth-status`，对接三个在面板上保留了"发起登录"按钮的插件（`workbuddy-ai-provider`、`traework-provider`、`zcode-provider`）
- 来源对象：本轮用户诉求，确认"插件面板自身的登录是否可移除、只保留导入/导出"
- 执行时间：2026-10-11 23:36 至 23:40（北京时间）
- 环境：生产服务器 `cpa-server`（`45.207.222.65:18998`）→ 容器 `cli-proxy-api`（host 网络，`127.0.0.1:8317`）；只读验证，未改代码、未改配置、未重启容器
- 性质：只读可用性验证（L1 拉起 + 状态机 + 桥接页可达性），**不含真实授权闭环**

## 4. 结论

1. **宿主统一 OAuth 登录入口对三插件均可用（L1 层面）**：`-auth-url` 全部 200、状态机不假成功、回调路由存在、桥接页可达。
2. **但"宿主登录页可完全替代面板登录"对三插件不成立或需区分**：
   - **traework**：宿主入口本身**就是**面板那套 browser-login 流程的别名（`login.go:73-75`），返回的也是插件桥接页。**面板按钮与宿主按钮是同一入口的两个壳**，删面板按钮不损失能力，但桥接页必须保留。
   - **zcode**：面板按钮打开的正是宿主登录流程要用的同一个桥接页。同理，面板按钮是桥接页的快捷入口，删按钮不损失能力，桥接页必须保留。
   - **workbuddy-ai**：面板 `/login/start` 与宿主 `handleStartLogin` 是**两段重复实现**（共用 `loginStates`）。宿主入口已能独立完成，面板入口是冗余重复，**可安全移除面板入口**。
3. **三个插件的"上游真实登录页"仅 workbuddy-ai 与 zcode 直连可达**；traework 因回调形状非标准（`authCodeInfo` JSON、无 state 回显、落死 loopback），**必须经插件桥接页 + 用户手动粘贴回调**，宿主原生粘贴通道对 Trae 形状是死路（`traework/login.go:12-18`、`traework/CHANGELOG.md:385` 注释原文）。
4. **本轮未做真实授权闭环**：真实登录涉及新增生产账号，属改变生产状态的操作，未在只读验证范围内执行。

## 5. 未覆盖说明

- **未验证真实授权闭环**：三插件均只验到"拉起 + 轮询 wait + 桥接页可达"，未真实完成一次账号登录。要判定"宿主登录页能否端到端替代面板登录"，必须各真实跑通一次完整登录（涉及新增生产账号）。
- **未验证 zcode 宿主自动回调落盘路径**：`checkHostCallbackPayload`（`zcode/oauth.go:221-248`）读取宿主落盘的 `.oauth-zcode-provider-<state>.oauth` 自动完成，本轮 T3 的伪造 POST 不能作为该路径成功的证据。
- **未评估删除面板入口的回归影响**：删按钮后需回归面板其余功能（导入/导出/测试/启停），本轮未涉及。
