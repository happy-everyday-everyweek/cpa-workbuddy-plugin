### 4.1 变异过程中暴露的方法论问题

首次变异误把 `"\n"` 写成真实换行，导致 Go 编译期报
`newline in string`。**编译期失败不能证明测试判别力**，已修正转义后重做，
最终结果如上表。同类问题在第二/三次变异中也出现过（`declared and not used`），
均补上引用后重跑，确保失败发生在测试断言而不是编译阶段。

## 5. 本轮发现并修复的真实缺陷

### 5.1 非流式响应正文重复（`TASK-103` 引入）

**现象**：`execute` 收集 `runStream` 的 emit 回调内容作为 trailing，
再拼到 `runStream` 返回值后面；而返回值本身就是同一份全文，
非流式响应变成「正文 + 正文」。

**根因**：把「图片走 emit 补发」这个设计连带假设成「emit 里只有图片」，
但 emit 同时承载正文增量。

**证据**：`TestExecuteDoesNotDuplicateContent` 初版实测输出
`"第一段第二段\n第一段\n第二段"`（期望 `"第一段第二段"`）。

**修复**：抽出 `runConversation` 作为共用执行体，返回
`(正文, 图片列表, 错误)`；`runStream` 用图片列表做收尾补发，
`execute` 直接把正文与图片 markdown 拼接。两个入口共用同一份
执行逻辑，不再依赖从回调里反解内容。

**回归**：`TestExecuteDoesNotDuplicateContent` 与
`TestExecuteAppendsImageMarkdown` 双用例锁定，变异验证通过。

### 6.3 执行期发现并修复的两个真实缺陷

#### 缺陷 A：生图取址位置错误（决定性）

**现象**：单元测试通过，但本地 CPA 端到端**只下发正文占位符，没有图片 markdown**。

**取证过程**（真实生图时 dump 17 帧）：

```
#10 type=stream  phase=event_delta  files=0  image=0 file=0 computerURI=true
#12 type=message phase=event_final  files=1  image=0 file=0 computerURI=true
汇总：帧数=17 image分片=0 files条目=2 含computer占位=2
```

**根因**：图片地址在 WS 载荷**顶层 `files` 数组**，不在
`content_v2.session.final.agent_message_event.content[]` 的 image/file 分片里。
实测 image 分片**恒为 0**；`content_v2` 只有一个 text 分片，正文是
`[图片](computer:///Coze/Drive/扣子/image/generate_xxx.jpg)` 占位符。
原实现只解析分片，WS 路径因此永远拿不到图。

**为什么单元测试没抓到**：我自造的 `replyFrameWithImages` 夹具把图片放在
`content_v2` 分片里——**夹具与真实上游形态不一致**，测试锁定了一个不存在的契约。
这是本次最重要的方法论教训。

**修复**（主流程正向演进，非打补丁）：
1. `frontierRawMessage` 增加 `Files []clawFile`；
2. `parseFrontierMessage` 解析完 content_v2 后，从顶层 files 取址并入 `msg.Images`；
3. `clawFileURLs` 签名从 `*clawMessage` 改为 `[]clawFile`，
   让 WS 顶层 files 与 message/list 的 files 复用同一取址逻辑。

**回归**：`TestParseFrontierMessageExtractsTopLevelFiles`（真实形态）、
`TestParseFrontierMessageImagesDedupeTopLevelAndContentV2`（跨来源去重）。

#### 缺陷 B：非流式正文重复（见第 5 节）

### 6.4 经验教训

1. **夹具必须来自真实上游**：自造的结构再自洽，也可能锁定一个不存在的契约。
   本次 `replyFrameWithImages` 就是反例。教训与既有「关键用例使用真实帧 hex」一致。
2. **单元测试全绿 ≠ 端到端可用**：缺陷 A 在单测里完全不可见，
   必须靠真实链路暴露。这也印证了「静态产物里存在 ≠ 运行时走这条」。
3. **失败时先 dump 真实结构，不要猜**：dump 一次 17 帧就把问题定位到了
   顶层 files，比继续推理分支形状快得多。

### 6.3 交接给真实环境时的验证步骤

#### 6.3.1 本地 CPA 环境（已实测打通，可直接复用）

以下步骤在 2026-10-18 23:02 实测通过，`FEAS-007` 已从「未验证」升级为「已探针验证」：

```bash
# 1) 构建插件 .so（WSL，必须 CGO_ENABLED=1）
wsl.exe -- bash -lc 'cd /mnt/f/cpa-plugin/coze && \
  CGO_ENABLED=1 GOOS=linux GOARCH=amd64 \
  go build -trimpath -buildmode=c-shared -ldflags "-s -w" \
  -o /tmp/coze-e2e/plugins/coze-provider.so .'

# 2) 构建宿主 CPA（关键：必须 CGO_ENABLED=1，否则无法加载插件）
wsl.exe -- bash -lc 'cd /mnt/f/CLIProxyAPI && \
  CGO_ENABLED=1 GOOS=linux GOARCH=amd64 go build -o /tmp/coze-e2e/cpa ./cmd/server'

# 3) 配置（plugins.configs 必须显式 enabled，仅 plugins.enabled 不够）
# /tmp/coze-e2e/config.yaml:
#   port: 18317
#   auth-dir: /tmp/coze-e2e/auths
#   plugins:
#     enabled: true
#     dir: /tmp/coze-e2e/plugins
#     configs:
#       coze-provider:
#         enabled: true
#   management:
#     allow-remote: false
#     secret-key: "local-e2e-key"

# 4) 启动并确认加载
wsl.exe -- bash -lc 'cd /tmp/coze-e2e && nohup ./cpa -config config.yaml > cpa.log 2>&1 &'
# 期望日志：
#   plugin loaded plugin_id=coze-provider
#   plugin registered plugin_id=coze-provider version=0.3.6
```

三个已踩过的坑（务必注意）：

| 坑 | 表现 | 正确做法 |
|---|---|---|
| 宿主用 `CGO_ENABLED=0` 构建 | `standard dynamic library plugin loading requires cgo on this platform` | 宿主必须 `CGO_ENABLED=1` |
| 插件放子目录 `plugins/coze/coze.so` | 管理接口 `path` 为空、不加载 | 扁平放 `plugins/coze-provider.so` |
| 只配 `plugins.enabled: true` | 插件不加载 | 还要 `plugins.configs.coze-provider.enabled: true` |

#### 6.3.2 账号接入（正确路径：走插件落盘，不手工拼宿主格式）

```bash
# 方式一（推荐）：把真实 Cookie 交给插件的落盘逻辑
# 插件的 writeAuthFileDirect 会写文件并通过 host.auth.save 让宿主注册
# 可复用既有 live 测试入口：
wsl.exe -- bash -lc 'cd /tmp/coze-e2e-auth-test && \
  COZE_LIVE_COOKIE="<真实 cookie>" go test -run TestLiveClawStream -v ./...'
```

**不要手工创建 `coze-*.json`**：宿主用 `coreauth.Auth` 直接解析该文件，
要求 `created_at` / `updated_at` / `last_refreshed_at` / `next_refresh_after` /
`next_retry_after` 全部为合法 RFC3339 时间；缺任一项会报
`failed to parse auth file ...: parsing time "" as "2006-01-02T15:04:05Z07:00"`，
随后路由层返回 `auth_not_found`。走插件落盘链路可自动满足。

### 6.4 已知风险

- **模型自主性**：claw 对话的模型由扣子侧页面选择器决定，请求体传 model 无效。
  浏览器实测中曾出现「请求发出但模型未生图」（黑猫那次 `files` 为空）。
  端到端时若未出图，应先确认页面选择器已指向生图模型，而不是改代码。
- **签名 URL 有效期**：`file_url` 带 sign 参数，实测有效期 30 天；
  日志与证据只记 `file_name`，不记完整 URL。
