# Coze 多账号只有一个可用 — 根因诊断

> 记录时间：2026-10-19 02:35
> 影响版本：coze-provider ≤ 0.4.4
> 修复版本：0.4.5

## 1. 现象

生产面板显示 3 个扣子账号，全部标记「可用」，但：

- 只有 1 个账号积分查询成功（2983 / 3000）；
- 另外 2 个账号积分查询返回 `code=700012006`，面板显示「积分查询失败」；
- 用户判断为「插件只能支持一个账户」。

## 2. 取证

### 2.1 先排除插件串号

逐个读取三个账号文件的 Cookie 会话指纹：

| 账号 | sessionid 指纹 | uid_tt 指纹 | user_id |
|---|---|---|---|
| coze-00b2… | 9c72d042fbb1 | b43dfea8f4fb | 3735510093922464 |
| coze-1185… | 111c6f431f5f | 9026c867c3a3 | 3735510093926560 |
| coze-d745… | 9532cd07f6e6 | 1ddda28c9e57 | 3084599620021148 |

三个账号的 Cookie 完全不同，**不存在互相覆盖或串号**。

### 2.2 直接用账号文件里的 Cookie 打上游

绕过插件，用各账号落盘的 `cookie_header` 直连
`/api/marketplace/trade/credit/balance`：

```
coze-00b2… → {"code":700012006,"msg":"登录认证失败"}
coze-1185… → {"code":0,"data":{...2983...}}
coze-d745… → {"code":700012006,"msg":"登录认证失败"}
```

结论：**两个账号的 Cookie 在上游确实已失效**，与插件是否串号无关。

### 2.3 时间线

```
02:10:46  账号3(coze-d745) 授权落盘，当时积分 3000（截图为证）
02:12:11  账号2(coze-1185) 授权落盘
02:17:00  账号1、账号3 定时续期 →「续期失败（第一步）：会话过期，请重新登录」
02:18:23  持续重复该失败
```

账号3 在授权后约 6 分钟即失效，中间发生过另一账号的授权动作。

### 2.4 用户确认

经确认：三个账号是**在同一个浏览器里先后登录授权**的。

扣子的会话是「单会话」语义——同一浏览器重新登录会作废旧
`sessionid`，因此先前授权的账号必然失效。这是上游账号模型决定的，
不是插件缺陷。

## 3. 插件侧真实缺陷

上游失效是外部状态，但插件有两个缺陷把它掩盖了。

### 3.1 登录态判据只看本地 Cookie 过期时间

```go
func (s *cookieStore) hasLiveSession() bool {
    for _, rec := range s.records {
        if !isCozeSessionCookie(rec.Cookie.Name) {
            continue
        }
        if rec.Cookie.Expires.IsZero() || rec.Cookie.Expires.After(now) {
            return true   // 没有 Expires ⇒ 永远通过
        }
    }
}
```

扣子的会话 Cookie（`sessionid` / `sid_tt`）**不下发 `Expires`**，
于是 `Expires.IsZero()` 恒为 true，本地判活永远返回「有效」。
面板上的 `auth_state` 因此对失效账号也显示 `ok`。

### 3.2 上游已明确拒绝，但状态不回写

续期日志已经明确记录：

```
定时续期失败 error=续期失败（第一步）：会话过期，请重新登录
```

但该结果只打成日志，没有写回账号状态。面板继续按 3.1 的本地判据
显示「可用」，用户无法从界面看出哪个账号需要重新授权。

## 4. 修复方案（0.4.5）

### 4.1 新增上游失效标记

`StoredAuth` 增加 `auth_invalid`：

```go
// AuthInvalid 表示上游已明确判定该账号会话失效。
AuthInvalid bool `json:"auth_invalid,omitempty"`
```

### 4.2 失效判定只认会话类信号

```go
func isSessionExpiredError(reason string) bool {
    text := strings.ToLower(strings.TrimSpace(reason))
    if text == "" {
        return false
    }
    return strings.Contains(text, "会话过期") ||
        strings.Contains(text, "登录认证失败") ||
        strings.Contains(text, "login verification is invalid") ||
        strings.Contains(text, "700012006")
}
```

超时、限流、5xx 等瞬态错误一律不置位——误标的代价是让用户去重新
授权一个本来可用的账号。

### 4.3 状态判定以上游为准

```go
func authStateOf(sa *StoredAuth) string {
    if sa == nil {
        return "expired"
    }
    if sa.AuthInvalid {
        return "expired"
    }
    // 本地 Cookie 判活（保留原逻辑作为兜底）
}
```

### 4.4 落盘与清除

- 续期失败且属会话失效 → `markSessionInvalid` 置位并落盘；
- 续期成功 → `applyRenewal` 清除标记。

两处都走 `accountReplaced` 防覆盖闸门，不会踩掉外部刚刚重新授权的凭据。

## 5. 验证

| 用例 | 锁定契约 |
|---|---|
| `TestAuthStateOf_RespectsUpstreamInvalid` | 上游判失效后必须报 expired |
| `TestIsSessionExpiredError` | 只认会话类错误，瞬态错误排除 |
| `TestMarkSessionInvalidPersists` | 标记真实落盘；瞬态不置位；续期成功清除 |

`python scripts/cgo-shim-build.py coze`：build / vet / test 全绿。

变异反证：移除 `authStateOf` 的失效分支、并把失效判定放宽为任意含「会话」
的文案，三个用例分别精确失败；还原后恢复全绿。

## 6. 账号侧结论

- 多账号在插件侧是**完全隔离**的（独立文件、独立 Cookie、独立积分缓存）。
- 「只有一个账号可用」的真实原因是**同一浏览器先后登录导致旧会话被上游作废**。
- 要让多个账号同时可用，必须在**相互隔离的浏览器环境**中分别登录授权：
  独立浏览器配置（多用户）、独立无痕窗口，或不同浏览器。
- 0.4.5 起，失效账号会在面板显示「待重新授权」，不再伪装成可用。

## 7. 残余事项

- 已失效的两个账号需要重新授权，且必须换用隔离的浏览器环境。
- 宿主侧账号选择策略（把请求分给哪个账号）不在插件内，本次未改动。
