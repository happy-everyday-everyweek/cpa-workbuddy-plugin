# coze 插件不输出 usage 致下游用量全部记零根因诊断

- 时间：2026-10-19 00:30
- 版本：coze-provider 0.4.0 → 0.4.1
- 环境：生产（cpa.luode.vip，容器 `cli-proxy-api`）

## 1. 现象

coze 模型请求已能正常返回正文（0.4.0 后连生图也已打通），但两条下游统计都是零：

- CPA 管理台 Token 用量面板：该模型「输入 0」、TPS `0.00`、成功率高但无 token；
- new-api 通用日志：该模型的 `Tokens` 列恒为 `-`，费用 `$0`，无法计费。

## 2. 取证

### 2.1 上游确实没有 token 数

| 来源 | 结论 |
|---|---|
| `POST /v1/model/list` | 只有模型元数据，无用量 |
| `get_multimodal_model_catalog` | 同上 |
| frontier WS reply 帧 | `content` 只有正文增量，`content_v2.session` 只有阶段/序号/快照，**无 token 字段** |
| `message/list` | 消息体只有 `files` / `content` / `sender`，无用量 |

这也与既有设计一致：`coze/main.go` 的 `executor.count_tokens` 直接返回 0，
注释写明「扣子没有独立的 token 计数端点」。

### 2.2 插件从未输出 usage

改造前 `buildChunk` 与 `buildCompletion` 都不写 `usage` 键。宿主侧
（`internal/runtime/executor/helps/usage_helpers.go:558` `ParseOpenAIUsage`、
`:485` `ObserveOpenAIStream`）只从响应体的 `usage` 字段取 token：

```go
usageNode := gjson.ParseBytes(data).Get("usage")
if !hasOpenAIStyleUsageTokenFields(usageNode) { ... }
```

字段不存在 → 直接返回零值 Detail → 面板与 new-api 都拿不到数。

**根因**：上游无真实用量 + 插件不输出估算值，两处叠加导致整链路记零。
这不是计费逻辑错误，而是**数据缺失**。

## 3. 修复

- `buildChunk` / `buildCompletion` 增加 `usage` 参数，非 nil 时写入响应。
- 新增 `estimateTokens`：CJK ≈ 1 字 1 token，拉丁 ≈ 4 字符 1 token。
- 新增 `buildUsage`：输出 `prompt_tokens` / `completion_tokens` / `total_tokens`，
  并附 `estimated: true` 便于人工区分估算值与上游实测值。
- 挂载位置严格遵循 OpenAI 约定：
  - 流式 → **只在终止帧**（`pumpClawStream` / `collectStreamChunks`），
    中间帧带 usage 会被客户端当作重复计费；
  - 非流式 → 响应体顶层 `usage`（`handleExecExecute`）。

估算函数与 doubao 插件既有实现保持一致，避免仓库内出现两套口径。

## 5. 遗留与边界

- **估算而非实测**：扣子上游无 token 数，本插件输出的是字符特征估算值，
  带 `estimated: true` 标记。若后续发现上游任何端点提供真实用量，应改为读真实值。
- **用量插件聚合视图未见 coze 行**：`token-usage-tracker` 的 `/stats/groups`
  里查不到 `coze-provider`，但其 `usage.handle` 日志确认已收到该 provider 的记录。
  这是该插件的聚合范围问题（它与 coze 无数据通道），不影响 CPA 与 new-api 的计费取值；
  如需在用量面板看到 coze，需另行评估该插件的统计口径。
