# 九大插件全景架构与演进计划总览（Gemini 插件已废弃下线）

结论：本项目生态收敛为涵盖 8 大 AI 服务商 Provider + 1 统一用量统计服务的九大插件全景生态（workbuddy、workbuddy-ai、traework、qoderwork、qoder-ai、cursor、zcode、copilot、workbuddy-token-usage）。原 gemini-provider 经评估因体积臃肿翻倍、依赖复杂 GCP 绑定且使用门槛极高，已彻底废弃下线并移除全部代码与 Release 资产；全部保留插件代码与单测均已在本地验证通过（cgo-shim 零错误）；本计划全面对齐最新架构事实，废除基于历史旧代码的陈旧假设（如保号池、硬编码模型、旧单模型探活等），确立全插件统一的调度容灾、多模型探活、用量上报与现代控制台规范，并规划后续稳妥演进路径。

## 二、 全仓库统一的五大核心技术规范（防偏差基线）

1. **统一账号调度与容灾规范（绝对废除保号池）**：
   - 历史上的 `preserve` 保号池主体已被**废除并从全部代码与面板中移除**（`preserve.go` 已删，兼容别名壳 `preserveWatchdogLoop` / `requestPreserveTick` 保留）；
   - 账号过滤契约：`scheduler.pick` 仅让可用账号承载流量——「测试失败」`test_failed`（workbuddy / workbuddy-ai / traework）、「冷却中」`cooling_down`、以及 qoderwork / qoder-ai 的「110 日调用上限 24h 冷却」`daily_cooling` **无条件硬排除且无任何回退**；
   - 全灭降级契约：当某插件所有候选账号均不可用时，必须返回 `Handled: false`（全灭 defer），将调度权交还 CPA 宿主进行跨 Provider 故障转移，禁止死锁在故障账号上；
   - 排序契约：存活可用账号一律按剩余可用积分**高积分优先**（健康账号积分更多者排前，未测积分 -1 排在最后），废除残血优先（Low-Credit-First）反模式；面板选中项一律同步该口径。
2. **分层探活与请求配额保护规范**：
   - **主动探活组（`workbuddy`, `workbuddy-ai`, `traework`, `zcode`）**：
     - 后台 Watchdog / Refresh Runner 活跃探活：从动态模型中取**全量模型按序**依次探测（2026-10-13 起由「最多 5 模型随机」演进为全量按序 any-success）；
     - 单次请求超时 20s，整轮叠加 30s 预算截止熔断；探活节流间隔统一 4 小时（2026-10-14 起由 30 分钟放宽），且无论成败均刷新节流时间戳（修正失败账号被反复重测的缺陷）；
     - 采用 **any-success** 快速判定：任意一个模型成功即判定账号健康，立即清除既有 `test_failed` 标签并终止循环；仅当全部候选模型均失败且账号仍有剩余积分时，才打上 `test_failed` 标签；
   - **配额保护免探活组（`qoderwork`, `qoder-ai`）**：
     - **严禁后台自动探活**：因 Qoder 官方账号具备严格的每日调用次数上限，`refresh_runner.go` 彻底移除后台定时发送推理探测请求的逻辑，防止后台静默耗尽用户每日配额；
     - 账号故障隔离完全由**真实请求期状态码**（401/429/5xx 阶梯退避冷却与换号重试）驱动；
   - **前端手动测试统一规范**：全插件面板卡片手动点击「测试」按钮统一弹出模型点选模态框，仅由用户显式触发单次定向测试，绝不产生非预期的后台轮询消耗。
3. **统一凭据物理落盘规范**：
   - 宿主 `host.auth.save` 序列化时会丢弃未声明的未知顶层字段（如 `test_failed`, `disabled`, `manual_disable` 等）；
   - 所有插件的账号修改（启停、打标、清标、删除）一律采用 `persistAuthDirect` 直写 `~/.antigravity_cockpit/<plugin>_accounts/` 物理 JSON 文件，由文件监听器自动同步到内存镜像，确保状态永不丢失。
4. **统一跨插件用量数据通道**：
   - Provider 插件在完成流式或非流式推理后，统一将用量元数据（`timestamp`, `provider`, `model`, `auth_id`, `tokens` 等）异步追加至 `<CLIProxyAPI root>/data/token-usage-feed.ndjson`（例外：copilot 当前 `usage_plugin: false`，无用量上报，见 G3）；
   - 统一由 `workbuddy-token-usage` 插件单向消费该文件，彻底避免跨插件共享数据库的文件锁冲突；
   - 供应商标识归一化：支持对 WorkBuddy、WorkBuddy AI、QoderWork、Qoder AI、Trae、Cursor、ZCode 进行全平台统一聚合（Gemini 已下线移除）。
5. **统一控制台 UI/UX 体验规范**：
   - 面板统一对齐深浅主题自适应、操作栏工具集、模糊搜索、卡片网格、一键全启全停、模型选择测试弹窗与 JSON 备份导入恢复。
