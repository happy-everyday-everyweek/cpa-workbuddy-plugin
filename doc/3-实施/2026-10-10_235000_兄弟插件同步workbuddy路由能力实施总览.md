## 一、当前计划最终方案的简要说明

以 `workbuddy` 的路由能力为唯一基线，向四个兄弟插件分批同步。推荐落点分三类：
1. **① traework 修复配置脱钩缺陷并完善对齐**：批次 A 已将默认值从 `off` 改为 `session` 并补充默认值断言；需追加 A5 补齐 `traework/config.go:175` 调用 `setSchedulerMode(v)`，彻底消除在 config.yaml 中配置调度策略静默失效的高危缺陷。
2. **② workbuddy-ai 只补测试资产**：生产代码已与 workbuddy 逐字同源，仅缺路由层自动化回归测试保护；复制测试套件并参数化 provider 前缀即可闭环。
3. **③ qoderwork / qoder-ai 做完整同构路由改造**：
   - **引入测试标签机制**：移植 `test_failed_tag.go`，并在 `active_ping.go` 补齐探活失败打标与成功清标。
   - **原位精简 watchdogLoop**：纠正原计划“迁移驱动源”的过度复杂认知，对齐 workbuddy 基线将 `preserveWatchdogLoop` 原位精简重命名为 `watchdogLoop`，原位保留 10 分钟周期的探活打标、计数落盘与旧标记清扫驱动。
   - **删除保号池（preserve）**：移除 `preserve.go` 及相关 15 个 Go 文件中的保号池分支与面板 UI，保留被外部复用的错误常量。
   - **补齐健康平摊排序与选卡**：在 `scheduler.go` 补充高积分优先排序（`accountHigherCredits`，未测 -1 排最后）与全灭 defer，并在 `active_auth.go` 补齐 `accountHigherCredits` 与 `ensureDefaultActiveAuth` 健康优选卡逻辑。

之所以这样切分：前两类是「低风险高确定性」缺口，可迅速闭环；第三类是「引入新机制 + 删除旧机制」的同构结构改造，以 workbuddy 为唯一蓝本逐函数移植，且 qoderwork 验证完全闭环后再镜像至 qoder-ai，杜绝两插件并行踩坑。

### 3.2 保号池删除的影响面与 watchdogLoop 原位精简方案

- **影响面范围**：涉及 15 个 Go 文件 + 1 个 `panel.html` + 3 个测试文件。
- **watchdogLoop 精简方案（方案优化）**：
  - *原计划认知偏差*：原计划认为 `preserveWatchdogLoop` 删除会导致计数落盘与 anomaly 清扫失去唯一驱动源，要求“先迁移驱动源再删 loop”。
  - *优化后基线方案*：对齐基准 `workbuddy/watchdog.go:137` 做法，直接将 `preserveWatchdogLoop` **原位就地精简重命名为 `watchdogLoop`**。删去循环内部的保号池状态计算与阈值翻转代码，原位保留 10 分钟周期的 `syncWatchdogScores`、`loadCountersFromDisk`、`purgeLegacyAnomalyFlags` 和 `flushCounters` 调用。零架构风险，零新抽象，改动量最小。
- **不可连带删除的共享代码**：
  - `preserve.go` 里的错误类型 `authFileErr`、`errAuthIndexRequired`、`errAuthMissing` 被其他写者与 `test_failed_tag.go` 复用，删除 `preserve.go` 时需将这 3 个错误定义迁移至 `active_auth.go` 或专用文件。
  - `keepalive.go` / `oauth.go` 中的 `preserveExpiry` 字段属于凭据保鲜期，与保号池同名但完全无关，严禁误删。
- **启动门清理**：`hostReadyForWatchdog` + `waitHostReadyForWatchdog` 清理后需确认无孤儿调用。

## 六、真实测试与验证计划

- **本地编译验证唯一通道**：Windows 无 gcc 环境下，编译执行一律使用 `python scripts/cgo-shim-build.py <plugin>`，只有 build、vet、test 全部返回 OK 且耗时真实才算通过。
- **新增测试必失败哨兵反证**：新增或移植每一个关键测试用例时，必须临时制造必失败断言（如期待错误值）→ shim 报错输出 FAIL 证实真实进入编译 → 恢复断言复跑验证通过。
- **面板前端语法检查**：`panel.html` 变更后，必须使用 `node --check` 进行纯语法校验，并通过正则检查 `data-action=` 绑定的函数在当前作用域内存在。
- **门禁要求**：每批次代码实施完成后，必须执行 `6-review` 风格回归并归档报告（STYLE: PASS），严禁跳步。

## 七、关键决策、设计细节与待确认点

1. **traework 配置联动缺陷（A5）的修复价值**：
   - 此缺陷属于既有代码中的隐蔽 Bug。如果不修，即使用户在配置中传入 `scheduler_mode: "off"` 或 `"session"`，调度器也永远只按启动时的静态默认值工作。通过 A5 将 `setSchedulerMode(v)` 补齐，彻底恢复配置控制权。
2. **qoderwork 选卡的业务一致性**：
   - 面板选卡默认值（`ensureDefaultActiveAuth`）必须与调度器排序逻辑保持一致。当前口径为**高积分优先**（`accountHigherCredits`，未测 -1 排最后），面板进入时自动选中的卡片即调度器首选使用的账号卡片，消除前端显示与后台路由的不一致。（原「低积分优先 + `accountLowerCredits`」口径已废弃。）
3. **watchdogLoop 原位精简的稳定性优势**：
   - 相比于原计划设计的“跨模块迁移驱动源”，原位精简保留了稳定的定时器和调度闭环，不仅避免引入新的协程生命周期管理，而且代码 diff 最小、最易 review。
4. **保号池历史配置兼容性**：
   - 与 workbuddy 基线保持一致，不再解析旧有的 `preserve_threshold` / `preserve_credits` 等配置，存量字段静默忽略，不引发解析崩溃。
