# workbuddy 成长中心重新接入需求与端点契约

- 需求编号：REQ-GROWTH-REVIVAL-2026-10-24
- 创建时间：2026-10-24
- 状态：契约已实测冻结，待实施
- 前序版本：0.16.0 引入（提交 `2e27bb1`）→ 0.17.0 移除（提交 `947a83c`）
- 实施总览：本计划 §5；风格回归：`doc/6-review/2026-10-24_120000_workbuddy成长中心重新接入_6-review.md`

## 1. 背景

父项目 workbuddy-provider 曾实现完整成长中心（7 段玩法），因用户反馈「成长计划没有生效，任务都没有完成」在 0.17.0 整体删除。本次重新接入，目标是修复根因而不是简单恢复旧代码。

## 2. 旧版失败根因（本轮实测确认）

旧版有三层缺陷，前两层此前已知，第三层是本轮新发现且是**真正的第一性根因**：

| 层 | 缺陷 | 后果 | 证据 |
| --- | --- | --- | --- |
| 1 | 完全没有行为上报（`POST /v2/report`） | 任务进度永不推进 | `git grep "v2/report" 947a83c^ -- workbuddy/` 零命中 |
| 2 | accept 只看 HTTP 状态码，不读 `data.results[i].status` | 失败虚报成功（0.16.3 已单独修） | `doc/4-bugs/2026-10-17_003000_...` |
| 3 | **从未调用 `buddy/first` 领养 Buddy** | 全部任务被 `prerequisite not met: first_buddy` 挡住，accept 永远不生效 | 本轮探针实测，见 §3.1 |

第三层的连锁效应解释了为什么「`14 accepted` 连续 6 轮恒定」：任务既没被真正接单（全部逐条 error），也没有任何进度，所以下一轮 pending 集合完全不变。

## 3. 端点契约（2026-10-24 实测冻结）

### 3.1 决定性实测：前置门槛与解锁链

实测账号：CN，未禁用，token 有效（uid 掩码 `d9d76e...`）。

**未领养 Buddy 时**，`POST /tasks/accept` 对每个任务返回逐条失败：

```json
{"code":0,"msg":"OK","data":{"results":[
  {"task_code":"chat_5","status":"error",
   "message":"prerequisite not met: first_buddy (no buddy instance found)"}
]}}
```

**执行 `report` → `buddy/agreement` → `buddy/first` 之后**，同一批任务立刻转为可接单：

| task_code | 领养前 | 领养后 |
| --- | --- | --- |
| `first_buddy` | `not_accepted`，progress=null | `claimed`，progress={1,1} |
| `chat_5` | `not_accepted`，progress=null | `accepted`，progress={0,5} |
| `create_canvas` | `not_accepted`，progress=null | `accepted`，progress={0,1} |
| `Library_read` | `not_accepted`，progress=null | `accepted`，progress={0,1} |

**上报推进进度**：领养后再发一次 report，`chat_5` 进度 `0/5 → 1/5`，`accept_status` 转 `in_progress`，结算延迟约 3 秒。

结论：**`before any task work, must complete first_buddy adoption`** 是本功能的第一条硬约束。旧版缺失它，等于所有任务都在空转。

### 3.2 域名与路径

四个 base 全部返回 200（服务端多域并存），因此域名不是失败原因：

| base | `/tasks` |
| --- | --- |
| `https://www.codebuddy.cn/v2/activity/growth` | 200 |
| `https://www.workbuddy.cn/activity/growth` | 200 |
| `https://copilot.tencent.com/v2/activity/growth` | 200 |
| `https://copilot.tencent.com/activity/growth` | 200 |

**选定 `{billingBase}/v2/activity/growth`**（即 `www.codebuddy.cn/v2/activity/growth`），理由：沿用插件既有 `billingBaseFor(sa)` 与 `billingHeaders`，零新增域名常量，且 Global 账号可自然复用 `billingBaseGlobal`。

### 3.4 任务对象字段（实测）

```
task_code, title, description, task_desc, task_type, tag, jump_url,
locked, accept_status, progress{current,target},
reward_credit, reward_energy, has_reward, reward_buddy,
badge_name, icon_url, is_new, is_pinned, valid_start, valid_end,
claimed_button_style, claimed_button_text, reward_popup_button_text,
template_id_fixed
```

**关键事实**：未接单任务的 `progress` 为 `null`，接单后变为 `{current,target}` 对象。因此判据必须同时处理两种形态，不能假设 `progress` 恒存在。

### 3.5 任务状态机（实测）

```
not_accepted --accept(需已领养)--> accepted --行为事件--> in_progress --达标--> (可 claim) --> claimed
```

实测取值：`not_accepted` / `accepted` / `in_progress` / `claimed`。

## 4. 本轮范围

- CN 账号 7 段：签到 / 旅行 / 任务 / 补登 / 兑换 / 抽奖 / 盲盒
- **Buddy 领养前置链**（report → agreement → buddy/first）——旧版缺失，本轮必须补齐
- 通用行为上报（`chat_request_send`）
- 进度口径领奖（`progress.current >= progress.target`）
- 面板单账号执行 + 摘要行
- 定时自动执行（`growth_auto` 默认 true）

## 5. 明确不在范围

- Global 账号（`skipped_global`）
- 参考项目 25 项专属动作（专家召唤链、指定模型真实对话、桌面指纹事件链）
- 小程序口径（`X-Client-Platform: miniprogram`）
- 发布与生产部署

## 6. 风险

行为上报本质是向 WorkBuddy 上游发送构造的 `chat_request_send` 事件，属伪造用户行为。参考项目 README 已声明因上游反代收紧停止维护。缓解：每号每轮最多 1 次上报、仅通用事件、账号间 1–3s 抖动、`growth_auto` 可一键停用。

## 7. 探针复现

```bash
# 只读矩阵
python scripts/probe_growth_endpoints.py --readonly \
  --uid-prefix <uid前6位> --auth-file <导出包.json>

# 幂等写（accept + 单次 report）
python scripts/probe_growth_endpoints.py --write-once \
  --uid-prefix <uid前6位> --auth-file <导出包.json>
```
