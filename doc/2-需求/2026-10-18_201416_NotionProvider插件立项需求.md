## 一、背景与目标

### 背景

Notion 在 2026 年已把 AI 对话做成独立入口（`app.notion.com/ai`），模型选择器覆盖 Claude / Gemini / GPT / SpaceXAI / 开放模型五个分组，包含 Sonnet 5.5、Opus 5.5、GPT-6.1 Sol、GPT-5.6 Terra、Gemini 3.7 Flash、Grok 4.6、Kimi K3、DeepSeek V4 Pro、GLM 5.2/5.3 等。这些模型对用户是订阅内额度，不额外计费。

经本轮真实检索与源码核实：

1. **零官方路径**：Notion Public API 与官方 MCP 只覆盖页面、数据库、搜索、评论，**不提供任何推理端点**。要接入只能逆向网页端。
2. **社区已有成熟反代**：GitHub 上至少 9 个可用项目，其中 2 个是 Go 实现，1 个（`notion_manager`）已做到 OpenAI + Anthropic 双兼容 + 多账号池 + uTLS 指纹。
3. **没有任何 CPA 插件形态**：`notion+cliproxyapi` / `notion+cpa+plugin` 搜索均无结果。c-shared 骨架必须自建，但可直接复制本仓库 `coze/` 目录。
4. **两套协议并存**：
   - **协议 A**：`POST /api/v3/runInferenceTranscript`，NDJSON 响应，真流式。7 个参考项目使用，含 2 个 Go 实现。
   - **协议 B**：`POST /api/v3/createAgentThread` + `listentToThreadTranscript` 长轮询，伪流式。仅 1 个 2026-10 的新项目使用。

本需求选定**协议 A 主线**，理由是：它是两个用户指定参考项目共同采用的协议、有 Go 实现可对照、支持真流式。

### 目标

新增 `notion-provider` 插件，把 Notion AI 账号能力封装为 CPA 的 OpenAI / Anthropic 兼容 Provider，与本仓库既有 12 插件同构，分四周期交付：

- **周期 0（传输层打底）**：uTLS 指纹传输 + Cookie 导入 + `getAvailableModels` 模型发现。
- **周期 1（对话闭环）**：transcript 协议转换 + NDJSON 流解析 + 单轮流式对话。
- **周期 2（多账号与生产就绪）**：账号池、故障转移、thread 复用、Cookie 滚动落盘、管理面板。
- **周期 3（发布）**：CI 接入、registry、图标、生产热重载验证。

## 二、范围

### 范围内

1. **Cookie 导入与持久化**：面板提供「导入登录态」入口，用户从浏览器导出 `token_v2` 等 Cookie 后粘贴/回传；插件解析、校验齐备性、探活后落盘至 `~/.antigravity_cockpit/notion_accounts/`。
2. **传输层**：uTLS `HelloChrome_Auto` + `http2.Transport` 自定义 `DialTLSContext`，配套浏览器指纹头（UA / `sec-ch-ua` / `sec-fetch-*` / Origin / Referer）。
3. **模型发现**：调用 `getAvailableModels` 动态拉取，按 `isDisabled` 过滤，对外加 `notion/` 前缀；配置内置静态 fallback 表（39 个代号）。
4. **协议转换**：OpenAI `messages` ↔ Notion `transcript`（`config` + `context` + `user` 三步）。
5. **流解析**：NDJSON 逐行读取，应用 `patch` 操作（`o`/`p`/`v`），区分正文 / 思考 / 搜索元数据，输出 SSE 帧。
6. **单轮与多轮**：首轮 `createThread=true` + 全量 transcript；后续轮复用 `threadId` + `isPartialTranscript=true`。
7. **账号池**：多账号存储、启停、删除、查看；阶梯冷却（30s × 连续失败次数，上限 10 分钟）。
8. **故障转移**：401/403/429/5xx/传输错误触发换号；`trust-rule-denied` 帧单独识别为账号级故障。
9. **管理面板**：账号导入、列表、状态诊断、模型展示、测试按钮。
10. **发布链路**：CI workflow 接入、`registry.json`、图标、生产 `plugin-store install` 热重载验证。

### 范围外

1. **不修改 CPA 宿主本体**（跨项目只读红线）。
2. **不在插件内实现 Notion 登录流程**——不做邮箱密码登录、不做 OAuth、不内嵌浏览器；插件只消费用户已登录的浏览器 Cookie。
3. **不做 Notion 页面 / 数据库 / 搜索 API**——本插件只做 AI 推理，不做 workspace 操作。
4. **不做自动注册、养号、批量开号**。
5. **不做 WebSocket 反向代理**——`notion_manager` 的 `/ai` 页面透明代理不在范围。
6. **不实现工具调用（tools / function calling）**——Notion transcript 不暴露 OpenAI 形态的工具协议，周期 0-3 均不涉及。
7. **不实现附件上传与图片输入**。
8. **不保证生产 SLA**——定位为自用/实验性 provider，文档需明确标注非官方、易碎、受 Notion 条款约束。

### 3.3 响应流语义

NDJSON 每行一个 JSON 对象：

- `type=patch`：核心增量。`v` 是 patch 数组，每项含 `o`（`a` 追加 / `x` 增量字符串 / `p` 路径替换）、`p`（路径，如 `/s/3/value/0/content`）、`v`（值）。
- `type=record-map`：终结快照，含完整 `thread_message.step`，可用于兜底取全文。
- `type=markdown-chat`：Markdown 形态的最终内容。

段落注册表机制（`notion2api/app/stream_parser.py:734-790`）：`o:"a"` + `path="/s/-"` 创建新段落时用 `v.type` 记录类型（`agent-inference` / `agent-tool-result` / `text`），后续 `o:"x"` + `/s/N/...` 按 index 查表归入对应段落。**不需要关键词猜测，也不需要状态机。**

## 四、约束

1. **uTLS 是防御性依赖**：`notion_manager/internal/proxy/transport.go` 无标准库 fallback；本机实测标准库也能到达应用层（P5/P6），但社区 A/B 显示有效凭据下指纹不匹配会得到 200 空流（`notion2api` issue #27/#28）。因此 uTLS 仍要实现，定位为抵御未来风控收紧与异地 IP 的防御层，而非当前已知硬闸。
2. **宿主 HTTP 桥不可用**：CPA 的 `host.http.do` / `host.http.do_stream` 只透传 method/URL/headers/body（`internal/pluginhost/http_bridge.go:108-140`），无法注入 TLS 指纹。插件必须**自建 `http.Client`**——已有先例：`doubao/completion.go:458`、`coze/credentials.go:107`。
3. **插件必须绕过宿主桥**：`qwenwork/host_bridge.go` 在 Windows 下已经强制走 direct（`runtime.GOOS == "windows"`），Notion 插件需要**所有平台**都 direct。
4. **浏览器指纹必须三处一致**：UA、`sec-ch-ua`、TLS ClientHello 的 Chrome 主版本必须对齐，任一漂移即静默失败（HTTP 200 空流）。
5. **失败模式是静默的**：TLS/头指纹不对时返回 **HTTP 200 + 空流**，不是 403（`notion2api` issue #27/#28 A/B 实证）。故障转移判据不能只看状态码，必须加「首帧超时」与「空流」判定。
6. **登录 IP 绑定**：Notion 把 AI 权限绑定到登录时的 IP，异地 Cookie 会得到 `403` 或 NDJSON 帧内 `subType: "trust-rule-denied"`。插件需支持按账号配置出口代理。
7. **cc BY-NC-SA 禁商用**：`notion_manager` 只能读行为，代码必须独立重写；`notion2api` 无 LICENSE，代码一行不能抄。可参考代码的只有 MIT 的 `shanchayijiu/notion2api` 与 `mughu-id/...`。
8. **ToS 风险**：Notion Personal ToS §2 明文禁止 reverse engineer / robot·crawler / thwart technological measure；§15 赋予单方无通知终止权。插件文档必须显著标注。

### 5.3 第三轮：真实凭据实测（2026-10-18，用户提供 Cookie）

**凭据**：用户浏览器导出的完整 Cookie header（1892 字节，9 个关键键齐全，`token_v2` 537 字符）。所有输出均脱敏，临时凭据文件用后即删。

**已通过项**：

| 探针 | 端点 | 结果 |
|---|---|---|
| Token 有效性 | `POST /getSpaces` | **HTTP 200**，20084 字节，返回 2 个 space |
| 模型清单 | `POST /getAvailableModels` | **HTTP 200**，26173 字节，**36 个可用 + 3 个禁用 = 39 个** |
| 模型代号表 | — | 与 `EXT-004` `model_registry.json` 的 39 条**完全吻合**（含截图中的 Opus 5.5 / GPT-6.1 Sol / GLM 5.3 / Kimi K3） |

**关键发现 1：`getSpaces` 双层结构，外层键不是 workspace id**

```
{"3fdd872b-...": {                  ← 外层：用户根 id（不是 workspace）
    "space": {
        "62a82b4e-7bdc-81d3-81ad-0003cbbddb60": {...},   ← 真实 workspace（商业版）
        "e98751a8-4fee-8161-aa20-0003aeb9538a": {...}    ← 真实 workspace（免费版）
    }
}}
```

用外层键会导致 `getAvailableModels` 返回 **403 `Space is not part of an organization`**；用内层真实 id 才返回 200。这是接入时必踩的坑。

**关键发现 2：一个账号可挂多个 workspace，额度独立**

| spaceId | 类型 | 高级额度（credits） | 基础额度 |
|---|---|---|---|
| `62a82b4e...` | `unlimited` | **300** | 50 |
| `e98751a8...` | `spaceAllowance` | **0** | 50 |

来源：`getAIUsageEligibilityV2` 的 `premiumCredits.totalCreditBalance`。

**阻塞项：`runInferenceTranscript` 只返回 `patch-start`**

在两个 space（含商业版 300 credits）上均只得到单行：

```json
{"data":{"s":[{"id":"3fd82b4e-...","owner":"regular","root":{"type":"none"},
  "selectedSkillPageIds":[],"sources":[],"trackedInstructionTreePages":[],
  "type":"agent-instruction-state"}]},"type":"patch-start","version":1}
```

随后 EOF，无任何 `patch` / `record-map` / `markdown-chat` 事件。

**已排除的假设（15 种组合全部失败）**：

| 假设 | 测试方法 | 结果 |
|---|---|---|
| config 字段缺失 | 5 / 38 / 58 字段三种粒度 | 全部只回 `patch-start` |
| threadType 错误 | workflow / agent / personal_agent | 全部只回 `patch-start` |
| config.type 错误 | workflow / agent / chat / personal_agent / markdown-chat | 非 workflow 均 400 或 0 字节 |
| debugOverrides | `emitInferences` true/false、无 overrides、带 page | 全部只回 `patch-start` |
| context_page_id | 随机 UUID / 固定 UUID | 无差异 |
| 额度不足 | 用商业版 300 credits 空间 | 同样只回 `patch-start` |
| 频率限制 | 冷却 60 秒后重试 | 恢复为 `patch-start`（连续打会 400，属短时限流） |
| 线程未落库 | `getThreadTranscript` 回查 | 400，线程确实未建立 |
| TLS 指纹 | 标准库 vs uTLS | 两者均 200，非传输层问题 |

`agent-instruction-state.root.type = "none"` 说明上游**找不到可用的 agent 指令上下文**，会话建立后立即终止。

**结论**：协议 A 在当前账号上**未打通**。已确认到「请求被接受、会话被创建、但推理未启动」这一层。剩余可能原因（按可能性排序）：

1. **账号尚未在网页端激活 AI**——用户截图显示商业版订阅存在，但 AI 功能可能需要先在 Notion 界面里主动开启一次（如打开 AI 面板完成引导）。
2. **`agent-instruction-state` 需要真实页面上下文**——`root.type` 应为 `page` 并指向一个真实存在的页面；当前 workspace 内 `getSpaces` 返回的 `block` 记录里没有可用 page。
3. **协议 A 已废弃，上游改用协议 B**（`createAgentThread`）——但协议 B 实测也返回 400 `ValidationError`。
4. **需要额外的客户端握手**（如先调 `loadPageChunk` 或 `saveTransactions` 建立上下文）。

**探针产物清理**：`.probe-notion/`、`.probe-biz/` 已删除；临时凭据文件 `notion_probe_cookie.txt` 已删除并回读确认。

### 5.4 实测结论对原计划的修正

| 原计划结论 | 实测结果 | 修正 |
|---|---|---|
| "uTLS 是硬依赖，标准库会被拦" | 标准库与 uTLS **都能到达应用层**，本机 40 次零拦截 | **下调为「uTLS 是防御性依赖」**：仍然实现（成本低、可对冲未来风控收紧与异地 IP），但不再作为「不实现就完全不可用」的硬闸 |
| "TLS 指纹不对会静默失败（200 空流）" | 假凭据场景下两者都拿到 401，未出现空流 | 该特性**只在有效凭据 + 指纹不匹配**时出现，本轮无法验证（需 GAP-001）；保留 AC-008 的空流判定 |
| "Cloudflare 可能强推挑战" | `cf-mitigated` 始终为空，无 HTML 挑战页 | **风险下调**：本机出口未触发 CF challenge |

**重要限制**：本轮全部使用**假凭据**，只能验证「传输层是否到达应用层」，不能验证「有效凭据能否拿到模型/回复」。后者必须由 GAP-001 解除后验证。

**探针产物清理**：`.spike-notion/`、`.spike-notion-plugin/`、`.spike-stability/`、`cpa-shim-*` 已全部删除并回读确认无残留；未写入任何生产资源。

## 七之二、协议打通的实证结论（2026-10-18 晚）

这一节是 **GAP-001 解除**的直接依据，也是插件实现的协议契约。

### 1. 根因：顶层协议字段缺失

`runInferenceTranscript` 只回单行 `patch-start` 并立即 EOF，根因**不是** TLS 指纹、不是 config 字段数、不是额度、不是频率限制。对比 `maverickxone/notion2api` 与 `SleepingBag945/notion_manager` 两个实现后，补齐以下 5 个顶层字段即恢复真实流：

| 字段 | 值 | 说明 |
|---|---|---|
| `threadParentPointer` | `{"table":"space","id":<spaceId>,"spaceId":<spaceId>}` | **必需**；首轮 `createThread=true` 时尤其关键 |
| `supportsCustomAgentNudgeTranscriptStep` | `true` | 必需 |
| `isUserInAnySalesAssistedSpace` | `false` | 必需（可为 null 之外的布尔） |
| `isSpaceSalesAssisted` | `false` | 必需 |
| `patchResponseVersion` | `2` | 与 `asPatchResponse:true` 配套 |

同时 `setUnreadState` / `saveAllThreadOperations` / `generateTitle` / `asPatchResponse` 也需为 `true`。

### 2. user block 编码：二维字符串数组

两个参考实现一致：

```json
{"id":"<uuid>","type":"user","value":[["用户文本"]],"userId":"<userId>","createdAt":"<RFC3339Nano>"}
```

`value` 必须是 `[[string]]`，不是 `[{"type":"text","content":"..."}]`。两种编码实测都能出正文，但二维格式才是网页端真实形态，插件统一采用二维格式。

### 3. NDJSON patch 语义（完整版）

流由 4 类事件组成：`patch-start`（全量快照）、`patch`（增量）、`patch-sync`（再次全量快照）、`record-map`（落库回执）。

`patch` 的三种操作：

| `o` | `p` 形态 | 语义 |
|---|---|---|
| `a` | `/s/-` | 追加新段落，`v` 是整段对象（含 `id` / `type` / `value`） |
| `a` | `/s/N/value/-` | 在段落 N 的 value 数组末尾追加一个元素 |
| `x` | `/s/N/value/M/content` | 字符串增量追加 |
| `p` | `/s/N/value/M/content` | 字符串整段替换 |

**关键陷阱（三条，都会导致正文丢失）**：

1. **索引不能用累积计数器**。`patch-start` 与 `patch-sync` 携带的 `data.s` 是权威全量快照，必须按 `id` 对齐已有段落；`patch-sync` 会重发已存在的段落（Gemini 场景一次流里有 4 个 `patch-sync`），用计数器会让后续 `/s/N/...` 全部错位。
2. **`agent-inference.value` 是异构数组**。元素可能是 `{"type":"thinking"}` 或 `{"type":"text"}`，文本项**不固定在索引 0**。GPT / Gemini / GLM 场景首元素是 `thinking`（含 `encryptedContent`），文本项经 `a /s/N/value/-` 追加到索引 1，后续增量走 `/value/1/content`。硬编码 `/value/0/content` 会把思考内容当正文、把真实正文丢掉。
3. **`agent-inference` 段缺省没有 `value`**。它先以 `{"type":"agent-inference","value":[{"type":"thinking",...}]}` 注册，正文是后续追加的元素；不能只看注册时那一帧。

### 4. threadId 与多轮

- 发送的 `threadId` 就是真实线程 id；`record-map` 的 `thread` 键与发送值一致（非 traceId）。
- 首轮：`createThread=true` + `isPartialTranscript=false` + `generateTitle=true` + `threadParentPointer`。
- 续写：`createThread=false` + `isPartialTranscript=true` + `generateTitle=false`，复用同一 `threadId`；**上下文正确延续**（实测首轮 `PONG-2026`，续写原样复述）。

### 5. 多 workspace 与套餐（GAP-006 实证）

| 空间 | spaceId | `premiumCredits.totalCreditBalance` | `basicCredits.spaceLimit/Usage` | 推理 |
|---|---|---|---|---|
| 商业版 | `62a82b4e-...` | 300 | 50 / 69 | 可用 |
| 免费版 | `e98751a8-...` | 0 | 50 / 5 | **可用** |

结论：`premiumCredits` 只反映订阅额度，**不是推理可用性的门槛**；`basicCredits.spaceLimit=50` 疑似基础消息上限（需在长跑中观察耗尽形态）。插件应逐空间查询并展示两者，供路由决策。

### 6. 模型覆盖（5 个家族实测）

| 家族 | 内部代号 | 结果 | 解析器输出 |
|---|---|---|---|
| Claude | `albuquerque-quinn` | 200 | `"OK"` |
| GPT | `omniberry-sundae` | 200 | 正确 |
| Gemini | `vertex-gemini-3.5-flash` | 200 | `"Hello! I am Notion AI..."` |
| DeepSeek | `baseten-deepseek-v4-pro` | 200 | 正文 `"OK"` + 971 字思考 |
| GLM | `fireworks-glm-5p3` | 200 | 正确 |

统一使用 `threadType=workflow`；`markdown-chat` 分支实测不可用（GAP-009）。

### 7. 模型不总是遵循指令

同一 prompt 在不同轮次，模型可能回答默认问候而非执行指令（如要求「只输出 PONG」却回 "What would you like help with?"）。这是上游 agent 行为，不是协议问题。**插件侧必须在 EOF 后做空正文/无意义回复判定**，并把它作为可重试的软失败。

## 八、风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| ToS 违规导致账号终止 | 高 | 文档免责；定位自用；不默认上生产 |

| 许可证污染 | 中 | EXT 清单逐项标注复制边界；只重写不复制 |
